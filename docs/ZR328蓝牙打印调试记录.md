## 现象演变

### 初始现象

1. 手机与 ZR328 系统配对成功。
2. App 可以列出打印机并显示蓝牙连接成功。
3. 连接成功时打印机蓝牙灯点亮。
4. 点击打印测试后提示：

   ```text
   蓝牙写入失败：broken pipe
   ```

5. 打印失败后打印机蓝牙灯熄灭。

### 多次尝试

分别尝试以下指令，第一笔数据都会立即断链：

- CPCL 初始化数据：208 字节
- SGD 语言查询/设置：45 字节
- ZPL 标签数据：93 字节

关键日志：

```text
BluetoothSppPrinter: SPP connected: 90:75:DE:21:95:D3
BluetoothSppPrinter: write failed, bytes=208
java.io.IOException: Broken pipe
```

## 已排查的方向

### 1. 打印命令格式

已测试：

- CPCL 行模式
- CPCL 页模式
- SGD `device.languages`
- ZPL

结论：任何第一笔数据都断链，与打印命令格式无关。

### 2. 打印机语言切换

已按以下流程测试：

```text
连接 SPP
sgdSet("device.languages", "line_print")
等待 4 秒
重新连接
发送 CPCL
```

日志显示 `sgdSet` 写入后立即 `broken pipe`，等待并重连后 CPCL 仍然立即 `broken pipe`。

结论：语言切换不是当前唯一根因。

### 3. Secure / Insecure RFCOMM 顺序

对比 ZR328 配套的通用 CPCL SDK 后发现：

- 通用 CPCL SDK 在现代 Android 上优先使用：

  ```java
  createInsecureRfcommSocketToServiceRecord(SPP_UUID)
  ```

- 当前自定义实现原本优先使用：

  ```java
  createRfcommSocketToServiceRecord(SPP_UUID)
  ```

该 secure 通道可以连接成功，但写入第一笔数据时被打印机断开。

已修改为：

```text
insecure RFCOMM 优先
secure RFCOMM 兜底
RFCOMM channel 1 反射连接兜底
```

### 4. 当前进展

修改为 insecure 优先后，第一次 CPCL 写入已经能返回 `0`。

最新日志确认：

```text
SPP connected: 90:75:DE:21:95:D3,method=insecure
CPCL init bytes=208,write=0
text1 write=0
text2 write=0
status query write=0
```

但打印机状态查询返回“无响应”，界面显示：

```text
第1次：直接CPCL=0，打印机状态=无响应
```

说明 insecure RFCOMM 已经解决 `broken pipe`，数据也已发送，但打印机没有按 CPCL 模式响应状态查询。

当前已调整为：当第一次 CPCL 状态查询不是“就绪”时，重新执行：

```text
sgdSet("device.languages", "line_print")
等待打印机重启
重新连接
再次发送 CPCL
再次查询 ESC h 状态
```

最新实机结果：

- 蓝牙连接和 CPCL 写入均已成功。
- 打印机已能出纸并打印部分文字。
- 当前测试内容仍有截断或多余字符，例如 `istest`、`1234..8`。
- 已将测试 CPCL 精简为：

  ```text
  ! U1 LMARGIN 0
  ! U1 SETLP 7 0 24
  Zebra ZR328 Plus Test\r\n
  1234567890\r\n
  ```

- 下一步重新构建后，直接看实际纸面输出，确认是否只剩两行预期文字。

## 下一步排查方向

### 1. 确认连接方式

连接成功页应显示：

```text
蓝牙SPP已连接(insecure)
```

如果仍显示 `secure`，说明 insecure 创建或连接失败，需要看 `BluetoothSppPrinter` 日志。

### 2. 确认“CPCL=0 后报错”的具体来源

需要区分：

- App Toast 报错
- App 状态框报错
- 打印机 LED 报错
- 打印机没有出纸
- 打印机盖子打开
- 打印机缺纸

推荐打印测试后发送打印机状态查询：

```text
! U1 getvar "device.status"
```

或使用通用 CPCL SDK 的 ESC 状态命令：

```text
0x1B 0x68
```

当前 App 已在 CPCL 写入成功后自动发送 `ESC h`，并解析缺纸、纸仓/盖子打开或就绪状态。

### 3. 用 WiFi 隔离蓝牙问题

ZR328 支持 WiFi，TCP 打印端口通常是：

```text
6101
```

测试方法：

1. 输入打印机 WiFi IP。
2. 端口填写 `6101`。
3. 发送同样 CPCL。

结果判断：

- WiFi 打印成功：问题集中在 Android 蓝牙栈、配对或 RFCOMM。
- WiFi 同样报错：问题可能来自打印机固件、介质、语言或打印头状态。

### 4. 打印配置报告

建议通过打印机 FEED 键进入 DUMP 模式，或使用 Zebra Setup Utilities 查看：

- `device.languages`
- `media.type`
- `head.latch`
- `media.status`
- 蓝牙最低安全模式
- 蓝牙固件版本

### 5. 使用官方通用 CPCL Demo 交叉验证

本机已有：

```text
/Users/liweifeng/Downloads/Android_CPCL_V1.13.01/CPCL_Demo_V1.13.01.apk
```

可在同一台手机上安装并连接同一打印机，确认：

- 官方 Demo 是否能够打印。
- 官方 Demo 使用哪种 RFCOMM。
- 打印机当前配置是否需要恢复出厂设置。

## 当前最可能结论

1. 第一阶段的 `broken pipe` 由 secure RFCOMM 与打印机不匹配引起。
2. 改为 insecure 后，第一笔 CPCL 已能写入。
3. 当前“写入成功但打印报错”更可能是打印机状态问题，例如：
   - 缺纸
   - 纸仓未关好
   - 介质类型与 CPCL 页模式不匹配
   - 打印机处于故障或需要重新校准状态

还需要根据 App 报错文字、打印机 LED 和 WiFi 交叉测试继续定位。

## 纸张校准与后续合并计划

### 已新增到 ZR328 调试页

- 纸张校准按钮。
- 参数包括：
  - 纸张宽度 dot
  - 标签高度 dot
  - 打印速度 0-5
  - 左边距 dot
  - 打印后出纸长度 dot
  - 连续纸模式
- 校准测试标签按钮。
- 参数使用独立 SharedPreferences：`zebra328_calibration`。

### 已移入的标签图片功能

ZR328 调试页已增加：

- 选择标签类型：PT、TC、TS、SMT、SMM、SMLI
- 输入对象 ID 获取标签图片
- 预览图片
- 打印当前图片
- 按生产记录 ID 批量打印
- 扫描生产记录标签批量打印
- 测试模式：最多 5 张小标签，中/大各 1 张

打印使用 `ZebraPrinter328Plus` 当前连接，不再依赖旧 `ZebraPrinter` 静态连接。

### 建议的合并策略

当前先不直接改 `NewGetPrintImageActivity`，因为：

- 旧打印机已经调好，直接替换连接层风险较大。
- ZR328 与旧 SDK 的设备模型白名单、RFCOMM 安全类型不同。
- 标签图片打印还需要 ZR328 专用 CPCL 图像链路验证。

第一阶段：

1. 在 ZR328 调试页完成纸张宽度、标签高度、打印速度校准。
2. 在 ZR328 调试页增加标签图片测试。
3. ZR328 图像打印稳定后，再抽取共用打印机发现页和校准设置。
4. 最后让 `NewGetPrintImageActivity` 根据打印机型号选择旧 SDK 或 ZR328 连接实现。

### 当前已知问题

- CPCL 数据已经可以发送并出纸。
- 打印速度较慢，已增加 `SPEED 5` 参数。
- 标签打印后可能停在末尾，需要根据校准测试标签判断是否需要 FORM、PostFeed 或调整标签高度。
- 点击一次会带出多张空纸，已定位为之前失败测试残留在打印机队列中的任务。
- 已在每次打印测试、校准标签、单张标签和批量标签前发送 `~JA` 清空打印机任务队列。
- 连续纸打印完成后会卡在当前位置，已改为连续纸模式默认发送 `POSTFEED`，不再发送 `FORM`。
